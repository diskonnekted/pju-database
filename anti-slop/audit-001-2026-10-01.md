## HIGH (Hard Gate)

**1. R-37 — Design built without owner direction.**
Evidence: no `DESIGN.md`; skin uses indigo `#4f46e5` + Inter + soft shadows + 16px cards (default AI-admin look).
Reason: identity should come from the product owner (DINHUB brand), not the model's default taste.
Fix: you give a direction (brand colors / mood / type), or we keep it labeled "draft" and set dials 1/1/1.

**2. R-25 — Muted text fails WCAG AA (real content unreadable).**
Evidence: `--dm-muted #94a3b8` = **2.56:1** on white, **2.27:1** on `#eef1f7` (need 4.5:1). Used for real content: "Total" label (css 121-124, 11px), "Laporan Belum Diverifikasi : N" (css 143, 12.5px), laporan dates+names (css 209, 11.5px), panel-options icons (css 79).
Reason: low-vision users and bright-light use are excluded.
Fix: darken muted to ~`#64748b`/`#5b6472` (>=4.5:1) or reserve `#94a3b8` for large/decorative text only.

**3. R-25 (non-text) — Progress-bar fill below 3:1 against track.**
Evidence: success `#16a34a` = **2.91:1**, warning `#d97706` = **2.81:1** on track `#eef1f6` (need 3:1, WCAG 1.4.11). info 3.25 / danger 4.27 pass.
Reason: the bar length carries data; a hair-thin edge hides the value.
Fix: darken success/warning fills (e.g. `#15803d`, `#b45309`) or darken the track.

**4. R-17 / R-38 — KPI progress bars show invented percentages.**
Evidence: hardcoded `width:75.7%` (php 68), `width:100%` (php 107), `width:100%` (php 126) not derived from data; `sr-only` texts are boilerplate/mismatched (php 89 says "39.9% Complete (success)" while the width is computed dynamically).
Reason: numbers/visuals without a real source are forbidden; empty beats deceptive.
Fix: compute each bar from real data (like php 88 does) or remove the bar and show only the real count; fix the sr-only text to match.

**5. R-38 / C-3 — Stray orphan label "RECENT USER ACTIVITY".**
Evidence: php 58 — bare literal text between the earnings row and the KPI stats; English, mislabels the section (it's KPI stats, not recent activity).
Reason: template leftover; content that is neither real nor an honest placeholder.
Fix: delete it, or replace with a real Indonesian section heading if the row needs one.

**6. R-24 / R-26 — Dead link (empty href).**
Evidence: php 22 `<a href="">perbaikan database dan proses import database lama!</a>` — empty href reloads the current page.
Reason: a link that goes nowhere is a broken promise.
Fix: point it at a real target, or drop the anchor and keep plain text.

**7. R-26 — Dead panel-options controls.**
Evidence: php 14 `<a><i class="fa fa-refresh"></i></a>` and php 29 `<a><i class="glyphicon glyphicon-option-vertical"></i></a>` — no href, no class, no JS hook → do nothing. (php 15 `panel-remove` is wired by Quirk and works.)
Reason: controls that look interactive but aren't.
Fix: remove the dead icons, or wire them to a real action with a visible label.

**8. R-26 — "Perlengkapan Jalan" quick tile is not clickable.**
Evidence: php 150-159 — title is plain text (no `<a>`), while all 7 sibling tiles link. The 52px icon + card look clickable but aren't.
Reason: inconsistent dead control; the only broken tile in the row.
Fix: give it a real destination (e.g. `/admin/perlengkapan`) or restyle it as non-interactive.

**9. R-32 — Keyboard access gaps.**
Evidence: href-less `<a>` (php 14, 29) are not focusable; quick-page cards are reachable only via the small title link — the icon/card body is not focusable or operable.
Reason: keyboard/AT users can't reach or operate these.
Fix: make the whole tile a real link/button (focusable), remove href-less anchors, ensure a visible `:focus-visible` ring (3:1).

**10. R-27 — No empty / loading / error states.**
Evidence: "Laporan Masyarakat" (php 261-273) renders an empty `<ul>` when `$pengaduan` is empty — no "Belum ada laporan" message; `#line-chart` (php 53) and Tagihan (php 35-43) have no error/empty fallback if data is missing.
Reason: data views must show all three states, each informative.
Fix: add an empty message + next action, a loading state, and an error fallback for each data view.

**11. R-03 — Mobile is a thin trailing override.**
Evidence: css 236-242 — a single `@media (max-width:767px)` that only tweaks padding + 2 font sizes; no tablet-band (768-1024) tuning; quick-page nav tap target is the small title text, not a >=44px target; relies entirely on the Bootstrap grid to reflow.
Reason: mobile must be a designed state, not a patch; tap targets need 44px.
Fix: give the narrow viewport a real reflow + scale, make whole tiles >=44px tap targets, verify no overflow at 360px and at the tablet band.

## MEDIUM (Purpose-Gate)

**12. R-06 — Typeface is Inter, the model's default pick.**
Evidence: css 33 `--dm-font:'Inter',...`; loaded via Google Fonts in header.php.
Reason: R-06 names Inter as the default roster; a typeface needs a brand-character reason.
Fix: choose a face that fits a government/public-service character (or keep Inter with a written reason).

**13. R-12 — Shadow on every panel.**
Evidence: css 55-62 — all ~17 panels carry `--dm-shadow` (`0 12px 32px`); css 166-168 adds a bigger hover shadow on tiles.
Reason: when everything is elevated, elevation communicates nothing; the page floats.
Fix: flatten most panels (border only), reserve shadow for 1-2 elements that truly lift; write the elevation reason.

**14. R-04 — Generic / mismatched / duplicate icons.**
Evidence: `ion-cube` (Jenis Perlengkapan, php 146), `ion-android-compass` (Perlengkapan Jalan, php 156), `ion-arrow-graph-up-right` (ID Pel, php 186), and `ion-ios-list-outline` used for BOTH Survey tiles (php 206 & 216).
Reason: glyphs are generic and one is duplicated across two different destinations; relevance not written.
Fix: pick icons relevant to each destination, de-duplicate the two Survey tiles, write the relevance.

**15. R-01 — Decorative violet accent with no meaning.**
Evidence: css 184 `.page-reports .page-icon{ background:#f5f3ff; color:#7c3aed }` — a purple accent off-palette, purely decorative.
Reason: blue-violet is an AI-default accent; here it marks no state or hierarchy.
Fix: fold it into the palette, or make the tile tint mean something (or neutral).

## LOW (Quality Locks)

**16. R-29 — Palette exceeds 2-3 core + 1 accent.**
Evidence: indigo + success + warning + danger + info + violet (6 hues), driven partly by decorative per-tile tints (css 181-185) that encode no meaning.
Reason: a scattered palette has no hierarchy.
Fix: keep status colors only where they encode meaning; make decorative tile tints neutral or drop them.

**17. R-20 / C-3 — Generic dashboard shell, no focal hierarchy.**
Evidence: announcement + earnings + 4 equal stat cards + chart + 8 nav tiles + weather + list — the default Quirk dashboard shape; four equal KPI cards with no "most important" metric.
Reason: layout should follow the decision the admin makes here, not the template.
Fix: name the screen's job, promote the one metric that matters, demote the rest.

**18. R-31 — No written reasons for major decisions.**
Evidence: indigo, Inter, 16px radius, soft shadow, per-tile tints — none have a one-line reason recorded.
Reason: the keystone rule; a technique is allowed only when its purpose is articulable.
Fix: record a one-line reason per decision (done as part of fixing 1/12/13/16).

**19. C-1 (craft bundle) — small defects.**
Evidence: typo "perkembagan" (php 21, should be "perkembangan"); inline styles fighting the skin — `style="font-size:18pt"` (php 35, overridden by css `!important`), weather `font-size:14pt` / `margin-top:0 !important` (php 242-243); non-standard `<temp>`/`<air>` tags (php 246/249); mixed EN/ID labels ("Temperature:" vs "Kecepatan Angin:", php 246/249); weather icon hardcoded over `http://` (php 238, mixed-content + fixed "10d" icon shown before JS updates); generic CTA "Lihat Selengkapnya" (php 276, R-15) with a decorative arrow (R-08).
Reason: craft/consistency defects; mixed content can break on HTTPS.
Fix: fix typo, remove dead inline styles, use valid elements + consistent language, serve the icon over https with a real default/empty state, make the CTA specific.
